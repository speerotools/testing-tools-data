FAQ
Frequently asked questions
How does Harness Feature Management separate deployment from release?
Harness wraps new code in feature flag statements using open source SDKs. The code is deployed to production but remains hidden behind the flag until you choose to enable it. This means you can ship continuously without exposing unfinished or risky features to users.
What targeting options are available for feature flags?
Harness supports percentage-based rollouts, user segment targeting, and attribute-based rules. You can target by any user property your application passes to the SDK, define dependency conditions between flags, and combine rules to create precise rollout strategies.
How do gradual rollouts reduce release risk?
By exposing a new feature to a small percentage of users first, you can observe real-world behavior before full rollout. If metrics degrade or errors spike, you can instantly reduce the rollout percentage or kill the flag entirely, without a code rollback or redeployment.
How does Harness help teams manage flag lifecycle and avoid technical debt?
Harness FME's Feature Flag Cleanup Agent integrates directly into your Harness Pipelines to automatically detect stale flags based on rollout status, targeting rules, and inactivity metrics. Teams can run scheduled scan-only audits to build trust, then trigger cleanup workflows that generate individual draft pull requests for safe human review. By validating new systems through dual reads, verifying they match legacy behavior, and maintaining rollback capability, the agent removes dead code while keeping cleanup gated behind your existing code review process. This pipeline-native approach ensures flag hygiene becomes part of your release workflow rather than manual tech debt sprints.
What governance controls are available for feature flag changes?
Harness Feature Management and Experimentation includes role-based access control, approval workflows, integrated pipelines, OPA-style policies, and a full audit trail for every flag change. Teams can require sign-off before flags are enabled in production to enforce change management policies automatically.
