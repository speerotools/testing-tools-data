Seth Payne
New: Access Token Expiration
Access Token Expiration
A series of improvements to access tokens and the Authorization page have been released. Starting today, we are replacing the existing access token reset with a token expiry field that can be set and updated via the existing access token APIs and the new Authorization page UI. As part of this change, we are also marking the legacy reset API for future deprecation and transitioning it into end-of-life mode.
This release also adds access token expiry notifications sent according to your notification settings via Slack, email, or the in-app inbox. Notifications about upcoming token expiry will be sent 30, 7, and 1 day before the token expires to the token creator and account owner for PATs, and to the account owner for service tokens.
Why It Matters
Previous access token reset obscured the existing token and its expiry date. This release gives you more transparency and granularity in your access token lifecycle management.

Paul Loeb
Agent Optimization is now in public beta
Agent Optimization is now available in public beta, giving teams a systematic way to improve their AI agents by running iterative optimization passes across models, configurations, and prompts - and deploying the best-performing result directly from LaunchDarkly.
Agent Optimization lets teams run structured optimization experiments against their AI agents to find the best-performing configuration. Rather than manually tweaking prompts and models and guessing at what works, teams can configure an optimization run that systematically tests variations across models and prompt strategies, evaluates each result using a judge model, and surfaces the winner so it can be deployed immediately.
Agent Optimization works with the LaunchDarkly Python AI SDK and integrates with popular agent frameworks. Configurations can be managed entirely in the AgentControl UI and pulled at runtime, or defined inline in code without any UI setup required.

July 23, 2026
AI Engineering
Paul Loeb
Break down AgentControl monitoring by context
Know exactly which customer is driving your AI cost, latency, and usage. You can now filter and group AgentControl monitoring by context kinds, so you can see tokens, cost, latency, generations, and satisfaction for a single tenant, a single user, or any slice of your traffic, instead of only the global average.
Global averages hide what individual customers experience. One power user can drive far more token spend than a typical user, and that difference disappears in the aggregate. Now you can attribute cost and latency to the customer causing them, debug one tenant's behavior in minutes, and understand how usage differs across your customer base without writing custom queries against raw data.
What you can do:
Compare customers side by side. Group the dashboard by user, organization, or an attribute like plan tier to see how different customers use your AI features.
Zoom in on one customer. Filter to a tenant, a department, or a specific user and every chart and table follows. Search works even with thousands of customers.
Take the data with you. CSV export matches whatever you have filtered or grouped on screen.
To get started, open a config's Monitoring tab and use the filter and Group by controls.

July 21, 2026
Seth Payne
Terraform provider v3 is now generally available
LaunchDarkly Terraform provider v3 is now generally available. This release is a major rebuild on the newer Terraform Plugin Framework, replacing the older v2 SDK foundation and setting the provider up to support new LaunchDarkly capabilities more quickly.
With v3, teams can manage more of their LaunchDarkly configuration in Terraform, including eight new resources: Context Kinds, Release Policies, Metric Groups, Announcements, Big Segment Stores, OAuth Clients, Integration Delivery, and Flag Import.
This release also improves plan-time validation, helping teams catch some configuration issues earlier in the workflow instead of discovering them only at apply time.
For customers using approval workflows and role mappings, v3 adds support for segment approval settings on environments and scoped role attributes on team role mappings.
Because v3 includes breaking syntax changes, existing v2 configurations will need updates before they plan cleanly against v3. To help with that transition, v3 includes a migrate-tf-syntax command to rewrite Terraform configuration from v2 syntax to v3 syntax, and provider state upgrades are handled automatically on first apply without requiring destroy-and-recreate workflows.
Why it matters
Faster access to new LaunchDarkly resources in Terraform
Better validation before apply
Broader support for approvals, role mapping, and newer platform capabilities
