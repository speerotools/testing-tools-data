Databricks
Setting up Databricks
Copy page
Copy page
Configure a Databricks service principal, personal access token, and schema permissions to connect your Databricks SQL warehouse to Kameleoon.
Copy page
Copy page
Data warehouse integrations are available as a premium add-on for Kameleoon’s Web Experimentation and Feature Experimentation module. For more information, contact your Customer Success Manager.
Steps 1 to 3 happen in your Databricks account, and step 4 happens in Kameleoon. Kameleoon recommends that your Databricks administrator performs steps 1 to 3.
With the Databricks integration, you can simplify data retrieval for targeted campaigns and personalized user experiences.
Key benefits:
Lets you target visitors with audiences built from your Databricks tables.
Lets you use Databricks conversions as goal metrics in experiment results.
Sync frequency:
Databricks as a source:
Each Data Ingestion Task runs at the
Frequency
you set when you create it, for example per day. Kameleoon polls goal queries every hour and merges the collected conversions into experiment results once per day.
See Data Ingestion Tasks
.
Databricks as a destination:
Kameleoon sends exposure events to Databricks whenever one of your experiments exposes a visitor.
See how the destination works
.
​
Prerequisites
To configure this integration, you need the following information:
Databricks personal access token (PAT)
Proper access to create Databricks schema and grant access.
​
Setup
​
1. Create a personal access token (PAT)
Kameleoon will authenticate to your Databricks SQL warehouse with a personal access token. You should create a Databricks
service principal
and then create a PAT for that service account.
Once you create a service principal, you can generate a PAT with the Databricks CLI, using the Service Principal “Application Id” that you can find in the Service Principal management page of the Databricks UI.
databricks
token-management
create-obo-token
{Service
Principal
Application
Id}
--lifetime-seconds
7776000
--comment
"Token for Kameleoon service principal"
You create the token in your Databricks workspace and then enter it in Kameleoon. For the full procedure, see the Databricks documentation on
personal access tokens
.
​

When using Databricks as a source

kameleoon_configuration

3. Grant read access to your data
For Databricks as a source, grant access only to the customer tables or views used by your audience and goal queries. First grant usage on their schema:
GRANT

SCHEMA

my_catalog
.
user_data

;

SELECT

GRANT

.

GRANT

MODIFY

​
4. Enter your credentials in Kameleoon
In the Databricks integration settings of your project in Kameleoon, complete the
Credentials
fields:
Databricks Server Hostname
: the server hostname of your Databricks workspace.
HTTP Path
: the path to your Databricks SQL warehouse.
Personal Access Token (PAT)
: the token you created in step 1.
PAT expiry timestamp in milliseconds (optional)
: the expiry time of the token, as a Unix timestamp in milliseconds. This field is optional, and you enter the value yourself.
To replace a token, enter the new token in the
Personal Access Token (PAT)
field and click
Confirm
.
After you save, Kameleoon shows the credentials in a summary card. The card displays the hostname, HTTP path and PAT expiry, but not the token.
After the credentials are saved, you can send experiment exposure events to Databricks. See
Use Databricks as a destination
.
​
Network and security
Kameleoon authenticates to Databricks with a personal access token. Kameleoon supports IP allowlisting. If you implement
IP access lists
, contact your Kameleoon account manager, so they can provide you with the list of Kameleoon IPs you must authorize.
​
Data region
Kameleoon stores the data from this integration in the Kameleoon data region of your account, which is the US or the EU.
