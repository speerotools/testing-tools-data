🎛️ Filter Dashboards by Experiment Status
Dashboards can now focus on the experiments that are running right now.
What you can do now
Choose Add Filter → Experiment Status on any dashboard, including dashboards generated automatically from tags
Share the filtered view by URL, or save your selection as the dashboard’s default filter
Experiment widgets that don’t match the filter are dimmed in place, so your layout stays intact
Why this matters
Experiment overview dashboards get cluttered as tests start and finish. Now you can keep the view focused on running experiments without removing widgets by hand.
Try it out
Open any dashboard, choose Add Filter, and select Experiment Status.

👀 Preview Changes Before Requesting a Review
You can now verify a proposed gate or dynamic config change inside the review modal before you submit it for approval.
What you can do now
Toggle a preview with Visual and Diff views, and filter between Changes and All Rules
See compact comparisons that highlight the changed fields when requesting a review for rule changes
Find reviewers faster with a searchable selector for Teams and Individuals, with checkboxes and removable pills
Get a prompt in the review flow to turn on Slack notifications for reviews
Why this matters
Reviewers can only approve what they can clearly see. Now you can check exactly what you are proposing before you send it, which means fewer review rounds spent on mistakes you could have caught yourself.
Try it out
Request a review on a gate or dynamic config rule change and open the preview in the review modal.

🧹 Stale Dynamic Config Management
Dynamic configs can live for years without a clear cleanup point. Teams can now find likely cleanup candidates, understand why they were flagged, and decide what to do next.
What you can do now
Temporary, Permanent, and Stale lifecycle states, with filtering in the Dynamic Config catalog
Reason-specific guidance on the config page: configs with no recent checks can be archived, while intentionally long-lived configs can be marked Permanent
A team-defined inactivity window (15, 30, 60, or 90 days; 30 by default)
Periodic email, in-app, and Slack reminders based on notification preferences
Lifecycle fields and filters in the Console API
Note: This is advisory only. A stale label does not change evaluation, disable a config, or archive anything automatically. This rollout does not include Feature Gate-only automation such as auto-archive, code-cleanup prompts or PRs, or bulk cleanup.
Why this matters
This closes a governance gap that several customers have raised and makes cleanup easier without introducing runtime risk.
Try it out
Check out the Feature Management page in your Statsig Console to evaluate config staleness.

🔐 Self-Serve RBAC for the Statsig MCP
You can now manage MCP access directly in the console, with project-level and role-level controls.
What you can do now
Set a project-level MCP scope — No access, Read only, or Read and write — as the ceiling for all roles in that project.
Configure MCP access per role within that project maximum, including Member and custom roles.
MCP only exposes tools that the project scope, role permissions, and token scope all allow.
To configure:
Go to Project Settings > Roles to set Default Project MCP Scope, then open a role's Permissions > MCP to configure its access.
Why this matters
Before this, teams that wanted to give analysts or stakeholders AI-assisted exploration through the MCP had no way to cap what they could do. Now, you can give some users read-only MCP access for exploration while keeping write access to the people who need it.
Try it out
Go to Project Settings > Roles in the Statsig console to configure MCP access for your team.
Learn more in the
Statsig MCP Overview
.

🧪 Richer Experiment Configuration via MCP

and

now accept five additional fields, giving you fuller control over experiment setup through the MCP.

enabledNonProdEnvironments

secondaryMetrics
Why this matters
Now, you can set secondary ID types, identifier mapping, non-prod environments, secondary metrics, and external links without falling back to the console.
